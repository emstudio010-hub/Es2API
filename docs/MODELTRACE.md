# ModelTrace 模型指纹检测

## 能检测什么

ModelTrace 比较模型在特定挑战中的行为特征，估计它与固定候选类的相似程度。界面叫“模型智商控制台”，结果实际是指纹归因概率。它不提供 IQ、通用能力评分或供应商模型身份的确定性认证。

当前有两类比较路径：内置 CPA / LM Fingerpoint Detector 固定数据，以及管理员自定义文本参考库的相似度比较。多种调度策略用于决定何时执行检测，不是多套独立识别算法。

## 内置参考库

- 固定 CPA 提交 `4f8367642cc1e629c4ee15a975e5e0fc53c4ac16`。
- LM Detector 算法提交 `654c8334bb53951aaf04cbd61252d163649e1369`。
- 60 个候选类、36 道挑战，每轮选 3 道不同挑战。
- 每题一个 Responses 请求，不自动重试失败样本，保持账号绑定的 VM2 环境。
- `gpt-6.1-sol` 映射到 `gpt-6-astra`；当前库不能区分二者。
- 概率以候选集为条件，集合外模型也可能接近某个候选，不能据此证明真实模型。

数据、算法、MIT 原许可证和 manifest 见 `integration/resources/modeltrace/`。详细来源见 [PROVENANCE.md](../integration/resources/modeltrace/PROVENANCE.md)。未安装 CPA host、原生插件或 Codex hook；只复用本地算法与数据，不声称复现 CPA 全部 CLI 上下文。

## 自动触发

| 策略 | 触发条件 |
| --- | --- |
| 按次数 | 累计成功调用达到阈值 |
| 固定分钟 | 定时间隔到达；没有用户调用也可能发起检测 |
| 次数或时间 | 以上任意一个条件满足 |
| 次数且时间 | 调用数和时间条件同时满足 |
| 有调用才定时 | 当前窗口有成功调用且定时间隔到达 |
| 概率抽检 | 每次成功调用独立抽取，受冷却限制 |
| 空闲后首次调用 | 长时间空闲后的第一次成功调用 |
| 手动 | 管理员显式发起 |

控制台提供 10 个草稿预设，含 5/10/15/30/60 分钟等选项，可自定义分钟、每 N 次调用、概率、空闲窗口与冷却。选择预设只修改草稿，保存才生效；旧账号不因升级自动切换策略。冷却期间不补测。

模型可指定，也可从成功调用统计中选择常用模型；无统计时用回退值。默认配置与字段约束以 `integration/src/modeltrace-config.mjs` 为准，租赁账号需显式启用相应检测。

## 就绪、动作和历史

检测前核对执行器、模型、采样数、参考库、账号槽位和环境状态；未就绪不发请求。动作包括只观察、降权和暂停，需结合置信阈值及连续偏差次数。

采样过程中，槽位、创建代次、账号凭据指纹、出口、策略或参考库发生变化时，结果可入历史，但不执行基于旧上下文的动作。取消与最后响应同时完成时也不能继续执行账号动作。进程重启将未完成任务标为中断，不自动重放供应商调用。

历史记录保存样本哈希、长度、用量、方法和状态；不保存原始回答正文。成功调用通知采用持久事件拉取与去重，纳入检测进度。

### 样本进度与失败诊断

从 `2026.11.04-preview.2` 起，每个样本开始前保存序号、挑战 ID、开始时间和单样本时限。检测详情显示已完成数量；失败时显示停止位置、耗时、HTTP状态（如已收到），允许的连接错误类别和响应终态收纳在可展开诊断中。已经完成的样本保留哈希、长度、用量和耗时。旧记录没有这些字段时保持缺失，不根据历史502猜测失败位置或原因。

仅接受 `status=completed` 的 Responses JSON，或含 `response.completed` 且其响应状态为 completed 的 SSE。失败/未完成终态、拒答、空文本、非法格式或超过4 MiB的响应均停止本次检测，不用部分文本进行归因。HTTP错误正文不读取；原始上游错误、连接URL、令牌及任意异常代码不写入诊断。每个失败样本仍不自动重试，管理员需检查实例及检测时限后自行决定是否重新发起。

采样/比较失败不产生归因结果和账号动作，错误或取消会清空连续偏差证据。如果比较已完成而后续账号动作写入失败，详情保留比较结果及已记录动作，提示核对实际账号状态；不能把它称为采样失败或承诺自动回滚。

## 成本与当前状态

检测会使用你绑定的账号发出真实请求，消耗额度并影响并发。设置高频自动检测前应评估用量。当前历史第三样本 502 尚未闭环；本次公开发布未重做真实检测或测试，不应宣称 ModelTrace 已稳定通过生产验收。
