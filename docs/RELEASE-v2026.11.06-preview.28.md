## 宿主请求与凭据维护协调

- 目录同步、配额/重置券读取与消费、搜索/图片JSON请求接入原Kernel共享活动锁。入场后读取最新槽、凭据和出口，持锁到响应体读取完成；维护等待在途请求释放或有限等待后拒绝。
- 提供旧槽快照的调用方比较账号绑定、代次、固定代理、后端和创建时间；目录每次请求比较已选凭据，拒绝沿用已替换记录。配额缓存写回另取活动锁并检查原凭据与归属，防止旧结果写入变化后的实例。
- 401/403按既有策略需要刷新时，先释放活动读锁，再进入宿主刷新日志与独占控制；后续请求重新入场读取。未新增自动模型调用或换票策略。
- 搜索/图片入场冲突不自动触发跨槽重试。并发搜索刷新去重键增加projectRoot，避免不同工程的同名槽共用刷新任务。
- 已确认重置券消费成功，但后续缓存读取未确认时仍保留成功与警告，不因此重复消费。
- 新增[宿主请求协调](CREDENTIAL_ACTIVITY.md)，同步刷新恢复与锁文档。
