# 代理池并发持久化

## 保存前比较数据库快照

代理池保留内存工作集，但不再无条件用它覆盖 SQLite。`ProxiesRepo.loadSnapshot()` 在同一读取事务中取得代理行和池配置，并生成仅供服务内部使用的数据摘要。摘要不是账号身份，也不进入面板或日志响应。

`replaceAll()` 必须携带原快照摘要；在同一写事务中重新读取并比较，再一起保存代理行和配置。不同则返回 `409 proxy_pool_changed`，缺少摘要返回 `409 proxy_pool_snapshot_required`。SQLite 并发事务升级也可能直接拒绝写入；不会为通过操作而重放旧快照。行写入失败会回滚配置和绑定。

此变更没有新增数据库表、迁移或版本字段。启动时数据库或配置损坏会拒绝加载，不再用空池覆盖原数据。保存失败后丢弃未提交的内存预留，尝试重新读取数据库；重读也失败则禁用该份内存快照，后续操作必须重新成功读取才能保存。

常用查询、资源选择和修改入口会重新读取数据库快照，只在数据确实变化时替换内存对象。自动分配仍在创建槽位落盘前进行独占 `bind`；成功绑定必须来自成功提交，不能因候选查询曾经显示空闲就视为已经占有。

## 等待与副作用

- 健康探测和出口地理查询在等待后核对原快照以及代理对象；期间其他保存导致数据变化时放弃旧结果，不自动重新探测。
- 批量健康结果先留在局部变量中，全部等待结束后再同步应用和保存；IPv4/IPv6 地理结果也一起应用。并发绑定不会意外带入未完成的查询结果。
- 停用、恢复调度和运行错误断开回调在持久化成功后才执行；失败保存不会发出成功变更通知。配置补丁先完成全部校验，再修改工作集。
- 旧 JSON 导入也采用同一快照保存接口，不把配置与代理行拆成两次独立保存。

## 仍然需要验收的边界

本次仅进行了源码审查、语法/模块加载和归档核对。没有运行并发进程、故障注入、实际代理分配、地理查询或模型测试，不能把代码机制称为已经完成并发行为验收。

所有写同一数据库的控制进程都必须升级；旧代码仍可无条件重写数据库，不能与新控制进程混用。快照比较处理的是同一 SQLite 的持久化冲突，不是不同机器或不同数据库之间的集群分配协议。每次刷新需要读取并摘要整份代理表，大型池的开销未压测。

回调在事务提交之后执行，但不在 SQLite 事务内；崩溃可能留下已提交数据而尚未触发回调。本次没有新增持久回调队列，也没有将跨进程 VM 文件和容器操作纳入原子事务。探测中的出口通道修复在等待结束后检查快照，但其实际执行仍依赖运行层自身的协调。

独占代理资源行仍不代表已验证的独占公网 IP。不同代理凭据或端点可能共用供应商出口；本次不做真实出口查询，不自动更换账号固定 IP。
