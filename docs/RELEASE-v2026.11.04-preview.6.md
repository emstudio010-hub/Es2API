# Es2API v2026.11.04-preview.6

本版补齐宿主凭据刷新与独立 Kernel 进程之间的执行归属，减少并发使用同一个旋转 refresh token 的风险。

## 修改内容

- Kernel 启动、普通和流式请求共用每槽活动租约；等待宿主刷新时暂拒新请求，已有流保持至内部响应完整结束。
- 宿主刷新和显式重导入先取得维护权，等待已有请求排空并确认宿主 Kernel 退出，之后再读取最新凭据和换票。等待最多15秒，超时不为刷新打断已有请求。
- 实际 Kernel 请求在租约内重新 ensure，补上预先启动与真正请求之间被刷新停机的间隙。维护结束后按需启动。
- CLI 刷新同时核对原 access/refresh token 及唯一账号数，拒绝覆盖变化的记录；沿用 r5 加密交接与冻结恢复。

详见[凭据连续性](CREDENTIAL_CONTINUITY.md)。支持一个控制面进程管理本机槽目录；直接 socket、外部文件修改、多控制面进程及远端节点不在本机门禁的保证范围。

## 分发与验收

Linux 附件为 `Es2API-linux-x64-20261104-r6.tar.gz` 和 `.sha256`，按[Linux说明](../deploy-linux/README.md)备份后升级。

沿用 r5 前端/Go/Kernel 与固定 CLI。本轮仅语法、模块加载、源码和分发检查、只读健康清点；未执行测试、真实刷新/重导入/重建/推理、Linux安装或浏览器验收。并发轮转、排空超时及进程重启行为仍需运行验收。真实 CLI→API、用量、取消、跨账号隔离和 ModelTrace 历史502尚未闭环。
