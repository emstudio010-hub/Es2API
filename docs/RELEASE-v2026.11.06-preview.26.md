# Es2API v2026.11.06-preview.26

## 宿主 OAuth 换票保护

- CLI 接入目录/配额/搜索和管理刷新共用的宿主刷新流程；先取槽控制锁、排空并停止 Kernel，再核对旧凭据签名身份。
- 换票前以 AES-256-GCM 保存完整快照和意图；收到含 token 响应后先加密保存，再验签及比较用户/workspace、完整记录和槽归属。写入、读回核对和文件/目录同步完成后才归档日志。
- pending 位于槽目录之外，跨重启保留；正常读取/刷新/CLI或Kernel启动、checkpoint与删除会拒绝，摘要仍显示待恢复布尔字段。停止允许，恢复不自动启动。
- 管理员 POST /api/panel/vms/:id/oauth/recover 只处理已保存响应并重新验签，不再次换票、不调用模型、不返回凭据。prepared、未知结果或身份/CAS不符继续保留并拒绝。
- 刷新请求不跟随重定向。仅 RT 的旧导入入口改为要求完整可验签凭据，未消费 RT。非 stale 重试增加原身份索引核对。
- 本地 operations 备份增加加密日志；当前 pending 时拒绝恢复旧数据库/密钥。新增 [恢复文档](REFRESH_RECOVERY.md)，修正文档中已过时的“没有稳定身份索引”描述。

## 范围与验收

没有实际刷新、恢复、行为测试或新增模型调用。仅静态/模块加载、只读健康和发布核对；不改现有账号 token、槽、出口和设置，沿用二进制。prepared/无完整响应不能自动恢复；磁盘/断电/网络不确定性不能由日志凭空补回令牌，不能删除意图后重试旧 RT。

第三方预编译 Kernel 内部自行刷新仍未纳入本日志；全部目录/配额/搜索在途请求也未统一到同一原子活动锁。不透明 RT 归属、并发/崩溃/实际轮转/恢复及 Linux/Windows挂载目录 fsync 均未行为验收，完整生命周期身份锁仍未完成。有 pending 时不得回退到不识别日志的旧版本。

已授权的最近 gpt-6-luna 调用仍为 HTTP502/codex_cli_connection_failed，无正文/有效usage；本版不代表真实 CLI→API 已跑通。完整 caller/Key/分组/计费、跨账号隔离、自动并发 IP 分配、ModelTrace、UI及 Linux 安装/生产验收仍未全部闭环；HTTPS暂缓。

Linux：Es2API-linux-x64-20261106-r26.tar.gz 与 .sha256，不含用户 runtime、数据库或私密日志。
