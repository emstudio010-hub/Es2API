# OAuth 账号与独立账号池

## 管理入口

- `/admin/accounts`：OAuth 账号管理。导入、查看状态、删除，并进入对应账号池。
- `/admin/account-pool`：独立账号池列表，每个账号 ID 对应一个工作区。
- `/admin/account-pool/:workspaceId`：该账号的 Codex 实例、固定 IP、运行设置和发布入口。
- `/admin/provider-accounts`：原生其他平台账号管理，保留原数据和 API；入口收纳在账号管理页面。

新导入账号自动建立 `workspace-<account_id>` 独立执行分组，归属该账号。OAuth 凭据、容器、home 和固定出口仍沿用账号级隔离。新导入不能指定共享分组；历史分组、已有账号、凭据和 IP 不做自动迁移。

## IP 资源与自动分配

在“执行 IP 资源”导入 SOCKS5 代理，每行一条，例如 `socks5://username:password@host:port`。管理界面只读取允许的脱敏字段，导入结果只回传新增和跳过数量。

导入 OAuth 默认选择“自动分配空闲 IP”，也可以在创建时手动选空闲资源：

1. 排除本机直连、其他所有者、停用、失效和被策略阻断的资源。
2. 仅使用未绑定资源，健康状态已知正常的优先，其次为尚未探测的资源。
3. 根据所选出口获取时区，然后生成该出口对应的身份。
4. 时区查询可能异步等待，落盘前再次同步检查并独占绑定；并发竞争失败的一方返回 409，可重试。
5. 没有资源、时区未知或分配失败时停止创建，不导入凭据、不启动容器、不回退直连。账号记录保留，可补充资源后从实例页重试。
6. 首次实际绑定写入账号 binding；失败重试、重启、并发设置导致的重建仍使用已固定的代理 ID，不自动切换。

新账号池的出口连接信息禁止修改，禁止从其他管理入口解绑、替换或删除。先删除账号池实例后才能释放资源；显示标签仍可编辑。原生非账号池槽位继续沿用原来的容量规则。

独占的是代理资源记录。不同凭据或代理地址可能对应同一公网 IP，系统不会凭资源 ID 宣称公网出口不同；需要供应商提供真正固定、独立的出口。

## 内部管理 API

新增 `GET/POST /api/v1/admin/exit-resources`，经原管理认证与 Go 的显式路由白名单转发。POST 仅接受 `text`，不能借此传入 VM 绑定、管理 URL 或其他 VM2 参数。没有公开任意 VM2 转发入口。

## 本轮交付边界

遵循用户“不做测试”：只执行语法检查、Vue 类型检查、生产编译和本机健康/静态产物读取。未执行测试套件、浏览器验收、新 OAuth 导入、并发分配实测或供应商推理。Linux 旧 Release 与 GitHub 发布分支不会因本地改动自动更新。
## Codex CLI 执行后端

新账号导入时可选择 Codex CLI（预览），单账号并发固定为 1，实例中可查看所选后端。历史账号不自动迁移。能力与隔离边界见 [CODEX_CLI_BACKEND.md](CODEX_CLI_BACKEND.md)。

## 启动、停止与恢复

进入具体账号池的实例页操作；请求立即返回 202，页面自动刷新后台处理结果。停止/恢复会取消在途执行和 ModelTrace 检测。操作完成及同步状态后，手动暂停均保持；确认健康后可在运行设置重新启用调度。恢复 CLI 时先确认容器停止再清理残留请求目录，不删除正式 OAuth 和工作区文件。删除未确认的容器不会释放固定 IP 或删除凭据。
