# 宿主 OAuth 请求与凭据维护协调

## 已接入路径

`withCodexCredentialActivity` 复用每个真实 projectRoot/槽的 Kernel 共享活动锁和共享入场控制，不新增独立锁域。取得活动锁后重新读取槽记录，检查 pending 刷新、交接和停机标记，严格读取凭据文件。提供旧槽快照的调用方还比较账号绑定、创建代次、固定代理、执行后端和创建时间；变化则返回 `codex_metadata_snapshot_changed`，不发送旧请求。

preview.29将槽快照比较统一到 `codex-slot-snapshot.mjs`：包括账号绑定、代次、节点、后端、创建时间、运行时容器、时区/身份策略以及实际代理地址和认证字段，不只比较代理ID。快照使用排序后的私密摘要，不返回浏览器或日志；槽变化码为 `codex_slot_snapshot_changed`，凭据行变化仍为 `codex_metadata_snapshot_changed`。

| 路径 | 持锁范围 |
|---|---|
| GPT 目录同步 | 每个账号的每次请求及完整响应体读取；请求前比较已选中凭据快照 |
| 配额 / 重置券列表 | 重新读取当前凭据和出口，到两个响应体读取完成 |
| 重置券消费 | 单次 POST 及完整响应体；保持既有 redeem_request_id，不增加自动重试 |
| 搜索 / 图片 JSON | 每次 POST 前重新读取凭据、出口，直到完整响应体读取完成 |
| 配额缓存写回 | 重新取得活动锁，再核对原凭据与槽快照，随后同步写元数据；变化则拒绝写回 |

这些共享读者可以并发。宿主刷新、checkpoint、凭据覆盖、停止/删除使用原 control 与 Kernel 排空路径，必须等它们释放活动锁，或在有限等待后拒绝；不会因维护超时删除读者锁文件。搜索/图片因入场拒绝时停止本次槽选择，不把维护冲突当作新的跨槽重试理由。

## 刷新与后续读取

401/403 若按既有用户动作允许换票，必须先让请求的活动锁释放，再进入宿主刷新日志/独占控制；不能带着共享活动锁升级为独占，否则会等待自身。后续请求重新取得活动锁、读取新凭据并重新核对旧槽归属，不能沿用刷新前的网络闭包。目录多账号调用逐条比较原选中记录，不随意改选另一条账号。

宿主换票现在要求调用方传 `expectedVm`。控制锁内先核对原请求槽快照，再排空/停止Kernel；随后重读当前记录，派生实际代理URL，并在旧凭据验签等待后再次核对槽、完整凭据数组及出口。调用方旧 `proxyUrl` 不作为网络出口使用。托管槽额外要求canonical账号ID、正整数代次、独占固定出口与后端一致，拒绝本机直连。

新刷新日志附加 `slot_snapshot`；提交前和本地恢复时均检查。只有代理资源ID相同但地址/认证变化，也会保留日志并拒绝提交。旧版本日志没有该字段时继续其原绑定/完整凭据/验签规则，不篡改历史日志或虚构新快照。CLI无需换票的凭据准备也在控制锁内核对槽快照，并在验签等待后再检查。搜索刷新任务去重键包含projectRoot、槽ID和快照，归属/维护冲突不触发跨槽重试。

重置券消费已确认成功，而随后的配额读取因维护失败时，仍回传消费成功与缓存未确认警告；不会将读取失败视为需要再次消费。普通配额和目录只读查询的原有401/403刷新策略保留，没有新增后台任务、轮询或供应商调用。

## 边界

这里只覆盖表中已接入的 Es2API 宿主路径。第三方预编译 Kernel 内部自行刷新/网络活动未因此获得日志保护或身份验签保证；它没有加入 Node 活动锁，宿主只有在取得控制权并确认 Kernel 退出后才可换票。其他语言程序、同UID外部写入、旧控制进程、远端节点和不同文件系统不因此受控。部署时所有控制进程必须一致升级，永久锁文件不能删除。

凭据快照比较用于拒绝变化，不证明不透明 refresh token 的归属。未执行请求、并发、维护超时、故障、崩溃或真实刷新验收；模块可加载、健康200和归档摘要不能证明这些行为。真实 Codex CLI→API成功正文/usage仍缺失，不能因本次协调源码完成而声称已上线验收。
