# Es2API v2026.11.04-preview.14

本版收紧真实容器CLI执行的退出确认和请求目录复用。

## 修改内容

- CLI监督器以原子rename写入结构化退出回执，包含请求ID、随机nonce、CLI pid/pgid、退出码和零存活组成员状态，替换空done文件。
- 主进程wait后向原进程组发送KILL，等待watcher退出，并在/proc中最多5秒确认同组不存在非僵尸/死亡进程；无法读取或确认则不签发回执。
- 控制面在Docker管道关闭后最多等2秒读取回执，验证文件类型/大小、UTF8、格式、请求ID/nonce、状态和退出码；成功响应额外要求匹配的exited/0回执。缺失/矛盾回执不能成功，不估算用量、不重试。
- 健康与新请求复用检查使用同一回执读取器；未知或旧空done标记保留目录并阻止复用，仅明确恢复且确认容器停止后可清理。取消仍保留已知真实usage。
- 账号请求目录通过wx独占文件锁跨控制进程认领，覆盖凭据准备与执行清理；只有匹配回执且清理成功或尚未启动子进程才由原拥有者释放，未知占用不按PID/年龄自动回收。明确恢复在确认该容器停止后清理锁。

详见 [Codex CLI后端](CODEX_CLI_BACKEND.md)。现有账号仍使用Kernel；未迁移CLI，未改账号/IP/凭据/设置、DB结构或指纹算法。前端、Go、Kernel和CLI0.155.1沿r13，未重编译。

## 分发与验收

Linux附件 `Es2API-linux-x64-20261104-r14.tar.gz` 和 `.sha256`，参照 [Linux说明](../deploy-linux/README.md) 备份后升级。没有运行测试、真实推理/刷新/导入/迁移、实例生命周期、浏览器或Linux安装验收。

回执是本地监督器的确认，不是供应商或操作系统可信证明；它仅覆盖原CLI进程组，不证明主动脱离该组的后代退出，也不等于VM级隔离。尚未实际验收取消、超时、心跳丢失、回执异常或容器退出。排队/健康阶段保活仍待实现，真实CLI→API、用量/隔离及ModelTrace历史第三样本502未闭环，HTTPS暂缓。
