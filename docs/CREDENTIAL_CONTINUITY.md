# OAuth 刷新、重试与重建

## 凭据归属

导入凭据以 AES-256-GCM 加密保存在 integration SQLite；执行实例内的 `codex-credentials.json` 是运行中的 OAuth 副本，刷新可能更新 access/refresh/id token。最初的导入副本不能被视为始终最新。

preview.5 开始，生命周期重试使用 `if_missing=true` 和预期账号/代次/后端/出口绑定。执行面在同一凭据锁内检查实际文件：有唯一可用记录时保留它，不重新消费旧刷新令牌；空槽才导入。可识别的供应商账号 ID 冲突、记录数量异常、损坏或过大的文件会拒绝导入，保留原文件。此行为不代替供应商身份认证。

## 修改运行设置后的重建

1. 控制面暂停调度，要求没有在途租约，并取消等待该账号的 ModelTrace。
2. 执行面核对规范槽 ID、integration 账号归属、创建代次、独占出口和后端。
3. 先持久化 `credential_handoff` 冻结标记，再停止容器并确认结果。随后按可执行文件、精确配置参数、用户和 `/proc` 启动标识确认宿主分离 Kernel 退出；只移除 socket 不作为退出证明。
4. 容器及 Kernel 退出后读取唯一 OAuth 记录。交接响应只通过管理员专用的内部 `POST /api/panel/vms/:id/credential-checkpoint` 返回，并带 `Cache-Control: no-store`；不进入工作区摘要、日志或公共账号响应。
5. 控制面以账号/槽/代次/旧凭据指纹作比较条件，在一个事务内加密保存当前令牌、新指纹、存在标记和交接回执。写入失败或与其他账号的凭据指纹冲突时，不删除旧槽。
6. 提交后才删除旧槽，确认不存在后递增创建代次，用保存的最新副本重建。相同固定出口继续使用。

如果删除成功后控制面在清理映射前退出，下次只在已存在匹配交接回执时接受旧槽 404 并继续。没有交接回执时，不把旧槽缺失当成已保存最新凭据的证明。

## 中断与恢复

冻结标记先于停机落盘，即使控制面未收到响应、进程退出或数据库提交失败，原槽也会阻止后续宿主刷新、启动、重导入、清除凭据和 reset。管理员应在账号池重试同一次重建，让服务重新确认停止和交接。不要手动删除冻结标记或凭据文件。数据库提交的交接回执用于中断恢复，不包含明文令牌。

目录同步、配额、搜索、管理刷新和 CLI 的**宿主侧刷新入口**共用按账号槽划分的锁。网络交换完成后重新核对令牌记录，变化时不覆盖。

preview.6 开始，宿主刷新和显式重新导入还取得 Kernel 维护权：先阻止该槽新的 Kernel 启动和请求，最多等待15秒让已有请求完整结束，再确认宿主 Kernel 退出，最后读取最新凭据、换票和写入。流式请求的活动租约保持至内部响应流结束；等待超时不终止现有请求、不开始换票。维护结束释放门禁，下次调用在同一活动租约内重新确认启动和发送，避免预先 ensure 与实际请求之间发生停机竞态。手动导入已有凭据的槽也走此流程；if_missing 保留已有记录时不执行换票或覆盖。

这不是向外部 Kernel 注入文件锁：Kernel 正常运行仍自行刷新，宿主取得维护权后通过等待请求排空和确认进程退出排除同时换票。只支持一个控制进程管理同一槽目录；直接访问内部 socket、外部修改文件、多进程控制面以及远端执行节点不在本机门禁的保证范围。宿主退出后门禁不持久，但下次宿主刷新仍须重新排空并扫描实际 Kernel 进程。重建交接另有上述持久冻结机制。

## 范围与验收

### preview.7 的停止与删除

本机 Codex 槽在显式停止/删除及禁用出口前，先在实际槽记录持久写入 `codex_shutdown`：包含操作ID、stop/delete动作、时间与未确认状态，立即停止调度。随后取得 Kernel 门禁、取消 CLI，按进程身份确认分离 Kernel 退出，再确认 Docker 停止/移除，并等待内部 Kernel 响应与宿主 CLI 请求释放。只有这些步骤全部完成才写入确认状态；删除接口之后才清理账号目录、解绑IP、移除记录。

异常时保留记录、凭据和固定出口；标记跨控制进程重启继续阻止调度、刷新、重导入、Kernel/CLI启动和重载。重试原停止/删除操作可继续确认，不把未记录的子进程或socket消失视为退出证明。同UID进程的命令行无法读取时也不能确认退出。已确认stop可以通过账号池显式启动，启动入口在凭据锁内解除标记；delete或未确认stop不能开机。恢复实例复用停止确认后再启动；CLI只在容器停止和宿主请求释放后清理临时目录。

禁用本机Codex出口现在执行同样的确认停机；重新启用出口后需显式启动实例。普通宿主刷新仍使用preview.6的排空流程，不主动打断已有调用。重建凭据交接已持有凭据锁时复用该锁，避免再次获取造成死锁。

独立账号池的旧执行槽reset、credential/clear和显式覆盖OAuth入口返回 `account_pool_managed`，运行设置重建、凭据和账号维护统一从账号池/账号管理完成，防止旧reset重建记录时丢失integration归属或替换成另一OAuth。控制面生命周期的if_missing导入仍要求匹配预期归属/代次/出口；已有记录保留。原始非托管执行槽入口继续保留。现有账号不自动停机、迁移或重建。

交接目前只支持本机 Linux Docker Codex 槽；远端、KVM、native 和非 Linux 宿主会明确拒绝，保留原槽。现有 Windows本机部署的执行服务运行在 WSL Linux；这不等于独立 Linux 安装验收。

本版不自动轮转、迁移、重新导入或重建现有账号；只有管理员随后选择重建时才执行上述流程。凭据指纹算法仍只哈希令牌材料，交接保存新的令牌时指纹会更新，以便旧 ModelTrace 动作因凭据变化失效。稳定供应商身份去重仍未实现，不能按邮箱或未验证 JWT 自动合并账号。

本轮仅进行语法、模块加载、源码与分发文件检查及只读健康清点，未运行测试、真实刷新、交接、重建或供应商推理。并发、进程中断、刷新令牌轮转及真实 CLI→API 路径仍需独立端到端验收。
